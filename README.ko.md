# Virtual Fab — 가상 공정 데이터를 이용한 웨이퍼 양불 판정 모델 학습

> **연구 질문:** 저비용으로 생성한 가상 웨이퍼 데이터가, 고비용의 실제 웨이퍼 데이터를 대체할 수 있는가?
> **요약:** 대체할 수 있다. 물리를 의도적으로 틀리게 설정한 시뮬레이터의 데이터만으로 학습한 모델이, 실데이터 2만 장으로 학습한 모델을 12%p 앞섰다.

반도체 공정을 모사하는 시뮬레이터(가상 fab)를 구축하고, 그로부터 생성한 데이터로
EDS 단계의 양품/불량 판정 모델을 학습시킨 프로젝트이다. 시뮬레이터와
분류기(퍼셉트론, MLP, 역전파)는 scikit-learn이나 PyTorch 등 외부 ML 프레임워크
없이 **numpy만으로 구현**하였다. 프레임워크에 의존하지 않고 내부 동작을 직접
구현하는 것 자체가 본 프로젝트의 목적 중 하나이다.

**구성 요소**

| | 내용 | 위치 |
|---|---|---|
| 1 | **가상 fab** — 실행할 때마다 웨이퍼 2만 장 분량의 공정 데이터를 생성하는 시뮬레이터 | `simulation/` |
| 2 | **판정 모델** — 그 데이터로부터 양품/불량을 분류하는 모델 (numpy 직접 구현) | `ml/` |

**주요 결과**

1. 양품 조건이 여러 조건의 **동시 만족(AND)** 형태이므로, 초평면 하나만 그을 수
   있는 단층 퍼셉트론은 이 문제를 구조적으로 해결하지 못한다. 불량의 92%를
   놓쳤다. 은닉층을 가진 MLP는 해결한다.
   (→ [4절](#4-분류-모델-두-가지))
2. 반면 **특징을 적절히 설계하면** 퍼셉트론도 실용적인 수준까지 회복한다. 불량
   검출률이 8.00%에서 44.57%로 상승하였다. 표현력은 모델뿐 아니라 특징에도
   존재한다. (→ [5.5절](#55-파생-특징margin의-효과))
3. 시뮬레이터의 물리를 **의도적으로 현실과 다르게** 설정한 조건에서도, 가상
   데이터로 학습한 모델은 유효하였다. 실데이터를 한 장도 쓰지 않은 모델이
   실데이터 **2만 장**으로 학습한 모델을 12%p 앞섰다.
   (→ [6절](#6-시뮬레이터의-물리가-현실과-다를-때-sim2real))

**권장 읽기 순서:** 시간이 제한된 경우 1절 → 3.3절 → 6절만 읽어도 핵심 논지가
이어진다.

## 1. 배경과 문제 정의

일반적인 머신러닝 실습에서는 데이터가 이미 주어져 있다. 부족하면 더 수집하고,
품질이 나쁜 데이터는 폐기하면 된다.

반도체 공장(fab)에서는 이 전제가 성립하지 않는다.

- **웨이퍼 단가가 높다.** 데이터 한 줄을 얻으려면 웨이퍼 한 장을 수십 단계의
  공정에 실제로 통과시키고 측정까지 수행해야 한다.
- **불량 샘플이 특히 희소하다.** 수율이 높을수록 불량은 드물어지는데, 모델이
  학습해야 하는 대상은 바로 그 불량이다.
- **공정 조건을 변화시키며 수집하는 비용이 가장 크다.** 양산 라인의 온도나
  공정 설정을 의도적으로 변경하는 것은, 같은 조건에서 웨이퍼 수를 늘리는
  것보다 훨씬 비싸다.

따라서 다음과 같은 접근을 검토할 수 있다. **공정 물리를 근사한 시뮬레이터로
가상 웨이퍼를 저비용 대량 생성하고, 그 데이터로 판정 모델을 학습시키는 것이다.**
이러한 시뮬레이터를 산업계에서는 **디지털 트윈**이라 부른다.

본 프로젝트는 이 접근이 실제로 성립하는지를 시뮬레이터 구축부터 모델 평가까지
직접 구현하여 검증한다. 검증 대상 질문은 다음 세 가지이다.

1. 가상 데이터로 양불 판정을 **학습할 수 있는가**, 그리고 이 문제는 어느 정도의
   모델 용량을 요구하는가. (2~5절)
2. 시뮬레이터의 물리가 **현실과 어긋나 있어도** 그 데이터는 유효한가. (6절)
3. 유효하다면 실데이터를 **어느 정도까지 대체**할 수 있는가. (6절)

## 2. 배경 용어

본 문서를 읽는 데 필요한 반도체 관련 용어를 정리한다. ML 관련 용어는 처음
등장하는 위치에서 설명하며, 전체 목록은 [부록 C](#부록-c-용어-사전)에 있다.

| 용어 | 의미 |
|---|---|
| **웨이퍼(wafer)** | 반도체 소자를 형성하는 원형 실리콘 기판. 본 프로젝트에서는 **데이터 한 행 = 웨이퍼 한 장**이다. |
| **fab** | 반도체 공장(fabrication plant). |
| **EDS** | 완성된 웨이퍼를 전기적으로 측정하여 양품/불량을 선별하는 검사 단계. **본 프로젝트의 모델이 대체하려는 공정**이다. |
| **스펙(spec)** | 제품이 만족해야 하는 값의 범위. 예: 문턱전압 0.67 V 이상 0.73 V 이하. 물리 법칙이 아니라 **제품 요구사항**이므로, 사람이 정하며 공장이 이미 알고 있는 값이다. |
| **수율(yield)** | 생산된 웨이퍼 중 양품의 비율. |
| **run** | 본 프로젝트에서 **시뮬레이터를 한 번 실행한 단위**. 한 run은 웨이퍼 2만 장이며, 이 2만 장은 모두 **동일한 공정 조건**에서 생성된다. 이 성질은 [3.4절](#34-run-단위-traintest-분리)에서 중요하게 작용한다. |

## 3. 가상 fab의 설계

> 코드: `simulation/`

### 3.1 웨이퍼의 표현: 5개의 공정 파라미터

시뮬레이터는 한 번 실행할 때마다 웨이퍼 2만 장을 생성하며, 웨이퍼 한 장은 5개의
값으로 표현된다.

| 파라미터 | 의미 | 스펙 범위 |
|---|---|---|
| `Vth[V]` | 문턱전압. 트랜지스터가 켜지기 시작하는 전압 | 0.67 ~ 0.73 |
| `Oxide[nm]` | 게이트 산화막 두께 | 97 ~ 103 |
| `Leakage[nA]` | 누설전류. 소자가 꺼진 상태에서 흐르는 전류 | 10 이하 (상한만 존재) |
| `CD[nm]` | 게이트 선폭(critical dimension) | 43.5 ~ 46.5 |
| `Temp[C]` | 공정 온도 | 23 ~ 27 |

**5개 파라미터가 모두 범위 안에 있어야 양품이며**, 하나라도 벗어나면 불량이다.
즉 양품 조건은 AND 조건이고, 기하학적으로는 5차원 공간의 **상자(box)** 내부에
속하는지를 묻는 문제가 된다. 이 상자 형태가 [4절](#4-분류-모델-두-가지) 전체의
논지를 결정한다.

run마다 각 파라미터의 **중심과 산포**가 정해진 범위 안에서 무작위로 샘플링된다
(`simulation/config.py`의 `PARAM_RANGES`). 실제 라인의 상태가 시기마다 조금씩
달라지는 현상을 모사한 것으로, run이 다르면 데이터 분포도 달라진다.

### 3.2 파라미터 간 물리적 상관

5개 값을 독립적으로 샘플링하면 공정 데이터가 아니라 단순한 난수가 된다. 따라서
실제 소자 물리에 따라 파라미터가 서로 영향을 주도록 설계하였다 (`PHYSICS`).

- 산화막이 **두꺼울수록** → 문턱전압 **상승**, 누설전류 **감소**
- 선폭(CD)이 **좁을수록** → 문턱전압 **하강**, 누설전류 **증가** (short channel 효과)
- 온도가 **높을수록** → 누설전류가 **지수적으로** 증가

이를 통해 데이터에 실제 상관 구조가 형성되고, 모델이 학습할 대상이 생긴다.

### 3.3 라벨은 참값으로, 특징은 측정값으로

본 프로젝트에서 가장 중요한 설계 결정이다.

- **라벨(정답)은 참값으로 판정한다.** 시뮬레이터는 웨이퍼의 실제 물리값을 알고
  있으므로, 그 참값이 스펙 범위 안인지에 따라 양품/불량을 결정한다.
- **모델에 입력되는 특징은 측정값이다.** 참값에 센서 노이즈를 더한 값, 즉
  **테스터가 실제로 보고하는 수치**만 데이터셋에 저장한다.

실제 공장에서도 검사 장비가 보고하는 것은 측정값뿐이기 때문이다. 이 설계는 다음과
같은 결과를 낳는다.

> 참 Vth가 0.7301이면 스펙 상한(0.73)을 초과하므로 **불량**이다.
> 그러나 측정값이 0.7295로 기록되면, 데이터만 관찰하는 모델에게는 **양품**으로
> 보인다.

즉 스펙 경계 부근의 웨이퍼는 **측정값만으로 판정하는 것이 원리적으로 불가능하다.**
따라서 이 문제는 어떤 모델도 정확도 100%에 도달할 수 없는, 본질적으로 확률적인
분류 문제가 된다. 해가 자명한 문제가 되지 않도록 의도적으로 설계한 장치이다.

이 성질은 처리 순서로 보장된다. `main.py`에서 **참값으로 라벨을 먼저 판정한 뒤**
노이즈를 더해 특징 컬럼을 덮어쓴다. 이 순서를 바꾸면 성질이 무너진다.

### 3.4 run 단위 train/test 분리

학습/테스트 데이터를 분리할 때 웨이퍼를 무작위로 섞지 **않고**, run을 통째로
테스트 셋으로 분리하였다.

[2절](#2-배경-용어)에서 언급한 성질 때문이다. 한 run의 웨이퍼 2만 장은 모두 동일한
공정 조건에서 생성된다. 웨이퍼 단위로 분리하면 테스트 셋의 웨이퍼와 사실상 동일한
조건의 웨이퍼를 학습 단계에서 이미 관찰한 것이 되어, 시험 범위를 미리 본 것과 같은
상태가 되고 성능이 실제보다 높게 측정된다.

run 단위 분리는 "**학습 시 관찰한 적 없는 공정 조건**에 대해서도 판정할 수
있는가", 즉 일반화 성능을 측정하는 것에 해당한다.
(`ml/dataset.py`의 `load_train_test_by_run()`)

## 4. 분류 모델 두 가지

> 코드: `ml/`

### 4.1 단층 퍼셉트론

**퍼셉트론**은 가장 단순한 분류기이다. 입력값에 가중치를 곱해 합산하고, 그 합이
0보다 크면 한쪽 클래스, 작으면 다른 쪽 클래스로 판정한다. 기하학적으로는 공간에
**직선(고차원에서는 초평면) 하나를 그어 둘로 나누는 것**이 전부이다.

학습에는 **pocket 알고리즘**을 사용하였다. 일반적인 퍼셉트론은 데이터가 직선
하나로 완전히 분리되지 않으면 가중치가 수렴하지 않고 계속 진동하며, 학습 종료
시점의 가중치가 우연히 나쁠 수 있다. pocket 알고리즘은 학습 도중 **가장 성능이
좋았던 가중치를 별도로 보관**했다가, 최종 모델로 마지막 가중치가 아닌 보관된
가중치를 사용한다. (`ml/perceptron.py`)

### 4.2 단층 퍼셉트론의 구조적 한계

1차원으로 축소하면 한계가 분명해진다. Vth 하나만 고려하면 다음과 같다.

```
불량 ←|————— 양품 —————|→ 불량
    0.67              0.73
```

양품 구간이 **가운데**에 있고 불량이 **양쪽**에 분포한다. 그러나 퍼셉트론이
표현할 수 있는 판정 규칙은 "이 값보다 크면 양품" 또는 "작으면 양품"뿐이다.
**"가운데 구간만 양품"이라는 규칙은 초평면 하나로 표현할 수 없다.**

파라미터가 5개로 늘어나면 양품 영역은 5차원 상자가 되고, 불량은 그 상자의 **모든
면 바깥, 모든 방향에** 분포하므로 한계는 더욱 뚜렷해진다. 즉 퍼셉트론이 이 문제를
풀지 못하는 것은 학습이 부족해서가 아니라 **구조적으로 불가능**하기 때문이며,
실제로 학습 중 오분류 수정 횟수가 끝까지 감소하지 않는다(매 epoch 약 5.9만 회).

### 4.3 MLP: 은닉층이 만드는 닫힌 영역

**MLP**(다층 퍼셉트론)는 입력층과 출력층 사이에 **은닉층**을 둔다(기본값 뉴런
16개). 은닉 뉴런이 각각 하나의 초평면을 담당하고 출력층이 이들을 조합하므로,
여러 초평면을 조합한 **닫힌 영역**, 즉 상자를 표현할 수 있다. 퍼셉트론이 하지
못한 바로 그 일이다.

구현에 포함된 요소는 다음과 같다 (`ml/mlp.py`).

- **역전파(backpropagation)** — 출력에서 발생한 오차를 이전 층으로 거슬러
  전파하며 각 가중치의 수정량을 계산하는 방법. 직접 구현하였으며, 구현의 정확성은
  수치 미분과 대조하여 검증하였다([5.1절](#51-재현성과-변동-폭)).
- **He 초기화** — 가중치 초깃값을 층의 크기에 맞게 설정하여, 신호가 층을 통과하며
  소멸하거나 발산하지 않도록 하는 기법.
- **L2 정규화** — 가중치가 과도하게 커지는 것에 벌점을 부여하여 과적합을 억제한다.
- **sigmoid 출력** — 출력을 0과 1 사이 값으로 변환한다. 이 값을 **P(양품), 즉
  해당 웨이퍼가 양품일 확률**로 해석한다. 이분법적 판정 대신 확률을 출력하는
  구조는 [5.4절](#54-판정-기준값cutoff과-운영점)에서 활용된다.

### 4.4 비용 비대칭과 클래스 가중

공정 관점에서 두 종류의 오분류는 비용이 다르다.

- **불량을 양품으로 판정하여 통과시키는 경우** → 고객에게 전달된다. 치명적이다.
- **양품을 불량으로 판정하여 폐기하는 경우** → 웨이퍼 한 장의 손실에 그친다.

그러나 데이터의 약 74%가 양품이므로, 별도의 조치가 없으면 모델은 "대체로 양품"
쪽으로 편향된다. 평균적으로 오차가 작기 때문이다.

이를 보정하기 위해 손실 함수에서 **불량 샘플 한 장을 양품 5장에 해당하는
가중치로** 계산하였다(`fail_weight=5`, class-weighted BCE). 결과는 다음과 같다.

| | 가중 없음 | 가중 5 |
|---|---|---|
| Precision (불량) | 86.24% | 70.50% |
| Recall (불량) | 71.25% | **87.47%** |
| F1 | 78.03% | 78.08% |

주목할 점은 **F1이 거의 변하지 않는다**는 것이다(78.03% → 78.08%). 즉 이 가중은
모델을 전반적으로 개선하는 장치가 아니라, **운영점을 옮기는 장치**이다. 불량
검출률이 71.25%에서 87.47%로 오른 대가로 정상 웨이퍼의 폐기가 늘었다(precision
86.24% → 70.50%). 위의 비용 비대칭을 고려하면 이 교환은 유리하지만, 공짜로 얻은
개선은 아니다.

## 5. 실험 및 결과

데이터는 12 run × 2만 장 = **24만 장**이며, 10 run으로 학습하고 나머지 2
run(4만 장, `run_001`·`run_008`)으로 평가하였다.

### 5.1 재현성과 변동 폭

본 절의 모든 수치는 `./reproduce.sh`로 생성한 데이터에 `python3 ml/mlp.py` 등을
실행한 결과이며, **같은 명령을 다시 실행하면 동일한 값이 나온다.** run마다 시드가
고정되어 데이터가 재현되고(`main.py --seed`, 사용된 시드는 `run_info.json`에 기록),
모델의 초기화·셔플도 기본 시드 0으로 고정되기 때문이다.

또한 손으로 구현한 역전파의 정확성은 **수치 미분과의 대조**로 검증하였다. 손실을
가중치에 대해 유한차분으로 미분한 값과 역전파가 계산한 기울기를 비교하며, 은닉층
수와 정규화 설정을 바꾼 6가지 구성 모두에서 상대오차가 `1e-6` 이하이다
(`python3 tests/test_gradients.py`).

다만 **시드를 바꾸면 값은 달라진다.** 초기화 시드 10개에 대한 MLP의 변동은 다음과
같다.

| 지표 | 평균 ± 표준편차 | 범위 |
|---|---|---|
| F1 (불량) | 76.88 ± 1.77% | 74.30 ~ 78.77% |
| Recall (불량) | 89.55 ± 3.16% | 84.71 ~ 94.03% |
| Recall @ cutoff 0.9 | **98.64 ± 0.58%** | 97.50 ~ 99.37% |

아래 표의 값은 모두 기본 시드(0)의 결과이므로, 표 사이의 차이를 읽을 때는 이 변동
폭과 대조해야 한다. 1%p 수준의 차이는 유의하지 않다. 한편 cutoff 0.9에서의 불량
검출률은 ±0.58%p로 거의 흔들리지 않는데, 이는 운영점을 recall 우선으로 잡았을 때
모델의 동작이 안정적이라는 의미이다.

### 5.2 평가 지표의 선택

본 데이터에서는 **모든 웨이퍼를 양품으로 판정하기만 해도 정확도가 74.23%**로
측정된다. 테스트 셋의 74.23%가 실제 양품이기 때문이다. 학습을 전혀 수행하지 않은
모델이 74점을 받는 상황이므로, 정확도는 판단 기준이 될 수 없다.

따라서 **불량을 얼마나 검출했는지**를 기준으로 평가한다 (불량 = positive).

| 지표 | 정의 | 해석 예시 |
|---|---|---|
| **Precision** | 모델이 불량으로 판정한 것 중 실제 불량의 비율 | 51.82% = 불량으로 판정한 것의 약 절반만 실제 불량이며, 나머지는 정상 웨이퍼를 폐기한 것 |
| **Recall** | 실제 불량 중 모델이 검출한 비율 | 8.00% = 불량 100장 중 8장만 검출하고 **92장을 통과시킴** |
| **F1** | 위 두 지표의 조화평균. 단일 수치로 비교할 때 사용 | 한쪽만 높으면 낮게 나온다 |

### 5.3 퍼셉트론과 MLP의 비교

| 지표 (불량 = positive) | 단층 퍼셉트론 | MLP (은닉 16) |
|---|---|---|
| Test 정확도 | 74.38% | 87.34% |
| Precision | 51.82% | 70.50% |
| Recall | **8.00%** | **87.47%** |
| F1 | 13.85% | 78.08% |

퍼셉트론은 불량의 92%를 놓쳤으며, 정확도는 "전부 양품으로 판정"하는
기준선(74.23%)과 사실상 동일하다(74.38%). 즉 학습을 통해 얻은 것이 거의 없다.
[4.2절](#42-단층-퍼셉트론의-구조적-한계)에서 예상한 결과와 일치한다.

퍼셉트론은 시드에 따른 변동도 크다(F1 16.95 ± 3.00%, 범위 13.85 ~ 21.23%). 이는
수렴하지 못하고 진동하는 모델에서 pocket이 고른 경계가 시드마다 달라지기
때문이다. 표준편차가 평균의 18%에 달하므로, 위 표의 단일 값(범위의 하단에 해당)은
대표값 이상의 의미를 갖지 않는다. MLP의 변동이 F1 기준 ±1.77%p인 것과 대비된다.

![decision boundary](docs/decision_boundary.png)

위 그림은 결정 경계를 Vth–Oxide 평면에 투영한 것이다(나머지 3개 파라미터는
중앙값으로 고정). 퍼셉트론은 평면을 **대각선으로 한 번 분할할 뿐**이므로 한쪽
방향의 불량을 전부 양품으로 판정한다. 반면 MLP는 실제 스펙 상자(점선)에 근접한
**닫힌 영역**을 학습하였다.

### 5.4 판정 기준값(cutoff)과 운영점

MLP는 확률 P(양품)을 출력하므로, **어느 확률 이상을 양품으로 통과시킬지**를 추론
시점에 결정할 수 있다. 이 기준값이 cutoff이며 기본값은 0.5이다. 이렇게 선택된
판정 기준을 **운영점(operating point)** 이라 한다.

cutoff를 **높이면** 통과 기준이 엄격해져 불량 검출률이 상승하지만(recall ↑),
정상 웨이퍼의 폐기도 함께 증가한다(precision ↓).

| cutoff | Precision (불량) | Recall (불량) | F1 |
|---|---|---|---|
| 0.1 | 91.86% | 60.78% | 73.16% |
| 0.3 | 79.86% | 78.38% | **79.11%** |
| 0.5 | 70.50% | 87.47% | 78.08% |
| 0.7 | 60.29% | 93.47% | 73.30% |
| 0.9 | 46.09% | **98.23%** | 62.75% |

F1만 보면 0.3이 최적이지만, 불량 유출이 치명적인 라인에서는 0.9로 설정하여 불량의
98%를 검출하는 편이 합리적이다. **어느 지점을 고를지는 지표가 아니라 두 오류의
비용이 결정한다.** 학습 시점의 `fail_weight`와 추론 시점의 `cutoff`, 두 개의
파라미터로 운영점을 조절하도록 구현하였다 (`python3 ml/judge.py run_011 0.9`).

특정 cutoff가 아닌 **전 임계값에서의 판별 성능**은 ROC·PR 곡선으로 평가하였다.
ROC AUC는 "임의의 불량 한 장과 임의의 양품 한 장을 뽑았을 때, 모델이 불량 쪽을
더 불량에 가깝게 채점할 확률"로 해석할 수 있으며, 0.5는 무작위 분류기에 해당한다.

![model evaluation](docs/model_evaluation.png)

| 지표 | 단층 퍼셉트론 | MLP |
|---|---|---|
| ROC AUC | **0.250** | 0.950 |
| PR AP (불량) | 0.238 | 0.890 |

퍼셉트론의 ROC AUC는 **무작위 분류기(0.5)의 절반 수준이다.** 퍼셉트론의 점수는 한
방향으로만 증가하는 반면, 불량은 상자의 **모든 면 바깥**에 분포하기 때문이다.
점수축의 한쪽 끝을 불량으로 간주하면, 반대쪽 끝에 위치한 불량은 오히려 가장
양품에 가까운 것으로 순위가 매겨진다. 즉 불량의 순위를 매기는 것조차 실패한다.

### 5.5 파생 특징(margin)의 효과

스펙 한계는 물리 법칙이 아니라 **기업이 이미 보유한 제품 요구사항**이므로, 이를
모델에 제공하는 것은 정보 누설에 해당하지 않는다. 따라서 각 측정값이 **가장 가까운
스펙 경계로부터 얼마나 떨어져 있는지**를 직접 계산하여 특징으로 추가하였다
(margin, 스펙 폭으로 정규화). 양수이면 스펙 내부, 음수이면 외부를 의미한다.

여기에 margin들의 **최솟값**(`MinMargin`, 가장 여유가 적은 항목)을 추가하면 판정
규칙이 다음과 같이 변형된다.

> **원래 규칙:** 5개 값이 모두 스펙 내부 → 양품 (5차원 상자)
> **변형된 규칙:** `MinMargin ≥ 0` → 양품 (**단일 축에 대한 선형 분할**)

초평면 하나로 풀 수 없던 문제가 초평면 하나로 풀리는 문제로 바뀐다. 결과는 다음과
같다.

| 모델 | 특징 | Recall (불량) | F1 |
|---|---|---|---|
| 퍼셉트론 | 원본 5개 | 8.00% | 13.85% |
| 퍼셉트론 | **+ margin 6개** | **44.57%** | **59.05%** |
| MLP | 원본 5개 | 87.47% | 78.08% |
| MLP | + margin 6개 | 91.16% | 77.54% |

퍼셉트론의 F1이 13.85%에서 59.05%로, 4배 이상 상승하였다. 구조적으로 풀 수 없던
문제가 실용 가능한 수준으로 바뀐 것이다. 다만 MLP(78.08%)에는 여전히 미치지
못하는데, `MinMargin`이 판정 규칙을 완전히 선형화하는 것은 **참값** 기준일 때이고
실제로는 노이즈가 섞인 측정값으로 계산되기 때문이다.

학습된 가중치를 확인하면 퍼셉트론이 `MinMargin`에 가장 큰 가중치(**+0.1564**)를
자동으로 부여하고 있으며, 이는 2위인 `Leakage`(+0.0382)의 4배에 해당한다. 규칙의
기하 구조를 특징에 인코딩하면, 모델이 그 축을 스스로 찾아낸다는 의미이다.

반면 MLP는 이득이 없다(F1 78.08% → 77.54%). 은닉층이 이미 상자를 표현할 수 있으므로
추가 정보의 효용이 없기 때문이다. **표현력은 모델과 특징 양쪽에 존재하며, 한쪽을
보강하면 다른 쪽의 요구량이 감소한다**는 것이 본 절의 결론이다.

한편 어느 쪽도 100%에는 도달하지 못한다. margin은 **측정값**으로 계산되는 반면
라벨은 **참값** 기준이기 때문이다([3.3절](#33-라벨은-참값으로-특징은-측정값으로)).
경계 부근의 모호성은 특징 설계로 제거할 수 없다.

> 실행: `python3 ml/perceptron.py --margins`, `python3 ml/mlp.py --margins`
> (`--margins`로 학습한 모델은 해당 사실이 모델 파일에 기록되며, `judge.py`가 새
> 웨이퍼에 동일한 변환을 자동으로 적용한다. CSV에는 원본 5개 컬럼만 저장된다.)

## 6. 시뮬레이터의 물리가 현실과 다를 때 (sim2real)

### 6.1 기존 실험 설계의 한계

5절까지는 학습과 평가가 **동일한 시뮬레이터 내부에서** 이루어졌다. 시뮬레이터가 곧
현실인 세계이므로 성능이 잘 나오는 것은 당연하며, 실용적 유효성은 아직 검증되지
않은 상태이다.

실질적으로 의미 있는 질문은 다음과 같다. **시뮬레이터의 물리가 현실과 어긋나 있을
때에도 그 데이터는 유효한가?** 현실의 물리를 완전히 재현하는 시뮬레이터는 존재하지
않으므로, 이 질문에 답하지 못하면 접근 전체의 근거가 성립하지 않는다.

### 6.2 두 개의 세계

이를 검증하기 위해 "현실 fab" 역할을 하는 두 번째 세계를 정의하였다.

| 항목 | 디지털 트윈 (가상 fab) | 현실 fab |
|---|---|---|
| 물리 상수 | `PHYSICS` | `REAL_FAB_PHYSICS` — **상이함** (아래 표) |
| 측정 노이즈 | `MEASUREMENT_NOISE` | `REAL_FAB_NOISE` — **대체로 큼** (아래 표) |
| 스펙 한계 | 공통 | 공통 (제품 요구사항이므로 두 세계가 동일) |
| 데이터 비용 | 무료, 12가지 공정 조건 | 고가, 예산 제한 (단일 조건) |
| 저장 위치 | `graph/run_*` | `graph/real/run_*` (`main.py --real`) |

**얼마나 어긋나 있는가.** 두 세계의 차이는 다음과 같이 설정하였다.

물리 결합 계수:

| 결합 | 트윈 | 현실 fab | 차이 |
|---|---|---|---|
| `vth_oxide` (산화막 → Vth) | 0.010 | 0.013 | +30% |
| `vth_cd` (선폭 → Vth) | 0.004 | 0.006 | +50% |
| `leak_oxide` (산화막 → 누설) | −0.30 | −0.36 | +20% |
| `leak_cd` (선폭 → 누설) | −0.05 | −0.03 | **−40%** |
| `leak_temp` (온도 → 누설) | 0.03 | 0.05 | **+67%** |

측정 노이즈:

| 파라미터 | 트윈 | 현실 fab | 차이 |
|---|---|---|---|
| Vth [V] | 0.005 | 0.007 | +40% |
| Oxide [nm] | 0.5 | 0.7 | +40% |
| Leakage (lognormal σ) | 0.10 | 0.14 | +40% |
| CD [nm] | 0.3 | 0.42 | +40% |
| Temp [C] | 0.4 | 0.3 | **−25%** |

즉 결합 계수는 20~67% 어긋나 있고, 측정 노이즈는 온도를 제외하면 40% 크다.
다만 이 불일치는 **계수의 크기만 다를 뿐 함수 형태와 변수 구성은 동일한**, 이른바
파라미터 수준의 불일치이다. 실제 시뮬레이터와 현실의 간극은 변수가 아예 누락되어
있거나 물리 모델의 형태 자체가 다른 **구조적** 불일치일 수 있으며, 그런 경우는 본
실험이 다루지 않는다([7.3절](#73-한계)).

주목할 점은 **트윈이 이 차이를 알지 못한다**는 것이다. 여기서 가상 데이터는 단순히
"노이즈가 포함된 데이터"가 아니라, **잘못된 물리 법칙에서 생성된 체계적으로 편향된
분포**이다. 그럼에도 유효한지를 확인하는 것이 본 실험의 목적이다.

### 6.3 비교한 세 가지 전략

현실 fab의 EDS 모델을 구축하는 세 가지 방법을 비교하였다.

| 전략 | 내용 | 비유 |
|---|---|---|
| **scratch** | 확보 가능한 실데이터만으로 처음부터 학습 | 기출문제 없이 응시 |
| **zero-shot** | 가상 데이터만으로 학습하여 실데이터를 전혀 사용하지 않고 투입 | 예습만 하고 응시 |
| **fine-tune** | 가상 데이터로 사전학습한 뒤 소량의 실데이터로 추가 학습 | 예습 후 실제 문제로 조정 |

평가는 현실 fab의 **held-out run 2개(4만 장)** 에 대한 불량 F1으로 수행하였으며,
실데이터 예산을 변화시키며 **10개 시드의 평균 ± 표준편차**로 보고한다
(`ml/sim2real.py`). 실데이터 pool은 현실 fab의 run 1개(2만 장)이다.

### 6.4 결과

| 전략 | 실데이터 250장 | 1,000장 | 4,000장 | 16,000장 |
|---|---|---|---|---|
| scratch (실데이터만) | 31.67 ± 2.54% | 35.22 ± 2.83% | 43.21 ± 3.67% | 60.20 ± 3.13% |
| **fine-tune (가상 사전학습 + 실데이터)** | **72.83 ± 0.82%** | **73.49 ± 0.98%** | **72.90 ± 0.68%** | **73.46 ± 0.28%** |

참조선: zero-shot **73.62%**, oracle(실데이터 2만 장 전량 사용) **60.78 ± 4.37%**.

![sim2real](docs/sim2real.png)

**첫째, 가상 데이터로 학습한 모델이 실데이터 2만 장으로 학습한 모델을 크게
앞선다.** 실데이터 250장을 더한 fine-tune이 72.83 ± 0.82%인 반면, 실데이터를 전량
사용한 oracle은 60.78 ± 4.37%이다. **12%p 차이이며 두 오차범위는 겹치지 않는다.**
실데이터 요구량이 사실상 **80분의 1**로 감소한 것이다.

**둘째, 이 우위의 원인은 데이터의 양이 아니라 공정 조건의 다양성이다.** 실데이터를
250장에서 16,000장으로 **64배 늘려도 fine-tune 성능은 72.8~73.5%에서 평평하다.**
실데이터 pool이 모두 **단일 공정 조건**(run 1개)에서 생성되었으므로, 아무리 많이
추가해도 모델이 새로 배울 것이 없기 때문이다. 반면 트윈의 가상 데이터는 **12가지
조건**을 포괄한다. 이는 실제 fab에서도 데이터 수집의 병목이 웨이퍼 장수가 아니라
**조건 커버리지**라는 사실과 부합한다.

**셋째, fine-tune은 zero-shot을 넘어서지 못한다.** 전 구간에서 −0.8 ~ −0.1%p로,
오차범위 안에서 **차이가 없다.** 즉 물리 불일치로 인한 손실이 소량의 실데이터
적응으로 회복되지는 않았다. 이는 둘째 관찰의 다른 표현이기도 하다. 적응에 사용할
실데이터 역시 단일 조건이므로, 모델이 그로부터 새로 얻을 정보가 없는 것이다.

종합하면, **가상 데이터의 가치는 시뮬레이터의 물리적 완전성에 의존하지 않는다.**
물리를 의도적으로 다르게 설정하고 실데이터를 한 장도 사용하지 않은
모델(73.62%)이, 실데이터 250장으로 학습한 모델(31.67%)의 두 배 이상, 실데이터
2만 장으로 학습한 모델(60.78%)보다도 12%p 높은 성능을 보였다.

## 7. 결론과 한계

### 7.1 본 프로젝트의 주장

> 가상 데이터의 가치는 물리적 완전성에서 비롯되지 않는다. 물리가 어긋난
> 시뮬레이터의 데이터만으로 학습한 모델이, 실데이터 2만 장으로 학습한 모델을
> 크게 앞선다. 그 격차를 만드는 것은 데이터의 양이 아니라 공정 조건의 다양성이다.

### 7.2 본 프로젝트가 주장하지 않는 것

- 본 실험은 "가상 데이터가 현실 물리에 부합하는지를 **검증**"하는 것이 아니다.
  오히려 물리를 **의도적으로 다르게** 설정한 뒤에도 유효성이 유지되는지를 확인한
  **강건성(robustness) 실험**이다.
- **fine-tune이 무용하다는 결론이 아니다.** 본 실험에서 fine-tune의 이득이
  관찰되지 않은 것은, 적응에 사용할 실데이터가 단일 공정 조건이었기 때문일
  가능성이 크다. 조건이 다양한 실데이터를 확보할 수 있다면 결과는 달라질 수 있다.
- 실데이터로 시뮬레이터 자체를 보정하는 것(물리 상수를 역추정하는 **캘리브레이션**)은
  방향이 반대인 별개의 문제이다. "모델을 현실에 적응시키는 것"과 "시뮬레이터를
  현실에 맞추는 것" 중 어느 쪽이 효율적인지는 본 실험의 범위를 벗어난다.

### 7.3 한계

가장 큰 한계는 본 실험의 "현실 fab" 역시 **시뮬레이터**라는 점이다. 물리 상수만
달리한 두 번째 가상 세계로의 전이이므로 엄밀히는 sim-to-**sim** 실험이며, 실측 공정
데이터에 대한 검증은 수행하지 않았다. 또한 두 세계의 차이를 **결합 계수와 노이즈
크기**로만 모델링하였으나, 실제 시뮬레이터-현실 간극은 변수 누락이나 시간에 따른
드리프트 등 더 구조적인 형태일 수 있다.

실데이터 pool이 **공정 조건 1개**로 제한된 것도 한계이다. 6.4절의 결론 중 상당
부분이 이 제약에서 비롯되므로, 조건 수를 늘린 실험이 필요하다.

### 7.4 향후 과제

- 실측 데이터(예: 공개 웨이퍼맵 데이터셋)에 대한 검증
- **조건이 다양한 실데이터**에서의 fine-tune 재평가 — 7.2절에서 지적한 한계의 직접적
  후속 실험
- 소량의 실데이터로 시뮬레이터의 물리 상수를 역추정하는 캘리브레이션과, 모델
  fine-tune 중 어느 쪽이 실데이터 효율이 높은지 비교
- PyTorch 재구현과 numpy 구현의 비교

## 부록 C. 용어 사전

| 용어 | 의미 |
|---|---|
| **특징(feature)** | 모델에 입력되는 값. 본 프로젝트에서는 측정된 5개 파라미터(및 선택적으로 margin 6개) |
| **라벨(label)** | 정답 값. 본 프로젝트에서는 양품(1)/불량(0)이며 참값 기준으로 판정된다 |
| **퍼셉트론** | 초평면 하나로 공간을 둘로 나누는 가장 단순한 분류기 |
| **pocket 알고리즘** | 학습 중 성능이 가장 좋았던 가중치를 보관했다가 최종 모델로 사용하는 방법 |
| **MLP** | 은닉층을 가진 신경망. 여러 초평면을 조합해 닫힌 영역을 표현할 수 있다 |
| **은닉층** | 입력층과 출력층 사이의 중간 층. 모델의 표현력이 발생하는 지점 |
| **역전파** | 출력의 오차를 이전 층으로 전파하며 각 가중치의 수정량을 계산하는 방법 |
| **gradient check** | 손실을 유한차분으로 미분한 값과 역전파의 기울기를 비교해 구현을 검증하는 방법 |
| **He 초기화** | 가중치 초깃값을 층 크기에 맞게 설정하여 신호의 소멸·발산을 방지하는 기법 |
| **L2 정규화** | 가중치의 크기에 벌점을 부여하여 과적합을 억제하는 기법 |
| **sigmoid** | 임의의 실수를 0~1 구간으로 변환하는 함수. 확률 해석을 위해 출력층에 사용 |
| **손실 함수** | 모델의 오차 정도를 수치화한 함수. 학습은 이 값을 최소화하는 과정 |
| **class weight** | 특정 클래스의 샘플을 손실에서 더 크게 반영하는 것. 본 프로젝트에서는 불량에 5배 |
| **cutoff** | 확률을 최종 판정으로 변환하는 기준값. `P(양품) ≥ cutoff`이면 양품으로 판정 |
| **운영점(operating point)** | 선택된 cutoff에 따라 결정되는 precision/recall의 균형점 |
| **Precision / Recall / F1** | [5.2절](#52-평가-지표의-선택) 참조 |
| **ROC AUC** | 전 임계값에서의 판별 성능을 단일 수치로 표현한 지표. 0.5는 무작위 분류기 |
| **과적합** | 학습 데이터에는 잘 맞으나 새로운 데이터에는 일반화되지 않는 상태 |
| **디지털 트윈** | 현실 시스템을 모사하여 구축한 시뮬레이터 |
| **sim2real** | 시뮬레이터에서 학습한 결과를 현실에 적용하는 문제 |
| **zero-shot** | 대상 도메인의 데이터를 전혀 사용하지 않고 그대로 적용하는 것 |
| **fine-tune** | 사전학습된 모델을 소량의 대상 데이터로 추가 학습시켜 적응시키는 것 |
